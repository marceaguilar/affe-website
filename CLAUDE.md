# AFFE website

Jekyll site for AFFE (Accounting and Finance Field Experiments), served by
GitHub Pages at [accfinfe.com](https://accfinfe.com).

## Layout of the repository

```
_config.yml              Site settings, the navigation menu, Google Sheets/Forms URLs
index.html               Home page (hero, upcoming events, mission)
404.html
CNAME                    Custom domain

pages/*.md               One file per page. Front matter only; the markup lives in the layout.
_layouts/*.html          One layout per page, plus default.html which wraps them all
assets/css/main.css      Site-wide styles and the colour tokens in :root
assets/css/*.css         Page-scoped styles (see "Styling" below)
assets/js/*.js           Page-scoped scripts
assets/data/*.json       Generated data files read by the page scripts
assets/img, pdf, xlsx    Static uploads

tools/new-research/      Data pipeline for the New Research tab (see its own README)
.github/workflows/       pages.yml deploys the site; new-research.yml refreshes the feed
```

There is no `_data/` directory and no `_posts/`. Content that varies lives
either in the page's layout, in `_config.yml`, or in a generated JSON file.

## How a page is put together

Adding a page takes three files and one config line.

1. `pages/<name>.md` — front matter only: `layout`, `title`, `permalink`.
2. `_layouts/<name>.html` — starts with `layout: default`, holds the markup.
3. `_config.yml` — add an entry under `navigation` to put it in the menu.

The nav menu is generated by looping over `site.navigation` in
`_layouts/default.html`. The active item is matched on `page.url`, so the
`url` in `_config.yml` must equal the page's `permalink` exactly.

## Styling

`assets/css/main.css` defines the palette as CSS custom properties on `:root`:

| Token | Value |
| --- | --- |
| `--color-parchment` | `#E8E5D7` (page background) |
| `--color-olive` | `#B8B794` (borders) |
| `--color-bark` | `#5A4A3A` (secondary text, accents) |
| `--color-sand` | `#D4C4A0` (badges, buttons) |
| `--color-sage` | `#8FA88F` (primary action colour) |
| `--color-olivewood` | `#2D2B1F` (header, headings) |

Always use the tokens rather than hard-coded hex values.

`main.css` is over 1,200 lines and is edited from several places, so new pages
should ship their own stylesheet under `assets/css/<page>.css`, scoped to a
single root class, and link it from the layout. `new-research.css` is the
example to copy: everything in it sits under `.nr`.

## Running it locally

```bash
bundle install
bundle exec jekyll serve
```

The site is then at `http://localhost:4000`. Note that `Gemfile.lock` and the
compiled extensions under `vendor/bundle` change whenever `bundle install` runs
on a different machine or Ruby version. Those diffs are build noise, not
content, and should not be committed.

## Deployment

Any push to `main` triggers `.github/workflows/pages.yml`, which builds with
Jekyll and publishes to GitHub Pages. There is no staging environment, so check
pages locally before pushing.

## The New Research tab

`/new-research` lists recent field experiments from SSRN and from the main
accounting, finance, economics and business journals. It reads a static JSON
file that is generated ahead of time and committed:

```
tools/new-research/config.yml   what to track (journals, keywords, windows)
tools/new-research/build.py     harvests, screens, verifies, writes the JSON
assets/data/new-research.json   the generated feed
assets/js/new-research.js       renders it with search, filters and sorting
```

Every entry is confirmed in both OpenAlex and Crossref before it is published.
The page makes no external API calls at load time. Full details, including how
to add a journal, are in `tools/new-research/README.md`.

To refresh the feed by hand:

```bash
python3 tools/new-research/build.py
```

## Working with other data sources

Working papers on `/working-papers` come from a hard-coded array at the top of
`assets/js/working-papers.js`. The file also contains a CSV parser for the
Google Sheets integration described in `WORKING_PAPERS_SETUP.md`, but that path
is currently switched off in favour of the static list.

## Conventions

- Page-scoped CSS and JS, named after the page, over additions to `main.css`.
- Colour tokens, never raw hex.
- Build generated data into `assets/data/` and commit it; do not fetch from
  third-party APIs in the browser.
- Keep external links as `target="_blank" rel="noopener noreferrer"`.

## Things to leave alone

- `vendor/` — committed gem sources and compiled binaries. Do not edit, and do
  not include its churn in a commit.
- `_site/` — build output, already ignored.
- `.jekyll-cache/` — local build cache.
